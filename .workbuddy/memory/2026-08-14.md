- **关键架构纠正**：`IntegratedApp`(app.rs) 只做模式切换，元素渲染委托给 `EditApp`(备课) 与 `DisplayApp`(授课)。真实渲染循环在 `drafftink-edit/src/render.rs` 与 `drafftink-display/src/render.rs` 的 `draw_element` 里。
- **发现**：`drafftink-display/src/render.rs:230` 早有**真实** kurbo+lyon `draw_svg_shape`（授课模式本就能渲染）；而 `drafftink-edit/src/render.rs:340` 只是**占位**（画个红叉包围盒）。所以备课（桌面默认）模式才是真正缺口 → 在 drafftink-edit 修。
- drafftink-edit/src/render.rs：把占位 `draw_svg_shape` 换成**真实 egui PathShape 渲染器**（用户 Option A）：`kurbo::BezPath::from_svg` 解析 → `kurbo::flatten(tolerance=0.05)` 采样成 `Vec<Pos2>` → 局部坐标+base.position 转 world、可选 base.rotation 绕中心旋转 → `egui::epaint::PathShape{points,closed,fill,stroke:.into()}` 经 `painter.add` 绘制；闭合形状填色、开放仅描边；`has_start/end_arrow` 用已有 `draw_arrow_head` 画三角箭头。解析失败走红色虚线占位矩形（`draw_svg_placeholder`+`draw_dashed_rect`），**零 panic**。新增 `kurbo="0.11"` 依赖（复用 workspace 版本，drafftink-display 已有的）。
- egui 0.29 坑（已踩并修）：`PathShape` 位于 `egui::epaint::PathShape`（非 `egui::PathShape`）；其 `stroke` 字段类型是 `egui::epaint::PathStroke`，须 `Stroke::new(...).into()`。
- app.rs：新增 **L 键**（仅备课模式）测试加载入口——`rfd::FileDialog` 选 .enbx → `drafftink_enbx::parse_enbx` → 遍历 slides/elements → `map_element_from_enbx` 得 `ElementData` → `to_legacy()` 转 `model::Element`（SvgShape 保留）→ 注入 `edit.doc.elements`；取消对话框则注入内置 `demo_svg_shapes()`（箭头/椭圆/星形/三角/矩形 5 个）。`render_canvas_area` 每帧按 `doc.page_size` 重算相机 zoom/offset 实现自动适配，故 loader 把 `page_size` 设为内容包围盒即可。
- 验证：`cargo build -p drafftink-desktop` 通过；**本次改动的两个文件（drafftink-edit/src/render.rs、drafftink-desktop/src/app.rs）clippy 零警告**。注意：`cargo clippy -p drafftink-desktop --all-targets` 仍会报 drafftink-display(workshop.rs)、drafftink-edit(annotation.rs 等既有行)、plugins 的**历史警告**（约 50 条），均与本任务无关、非本次引入，未动。
- 重要设计偏差（已向用户说明）：用户原要求渲染目标/路径在 app.rs 内直接遍历 elements；实际渲染在 drafftink-edit/drafftink-display，故渲染器落在 edit，app.rs 仅加测试加载钩子。
