## 重叠图形命中检测：选中上层元素（drafftink-desktop）
- 用户反馈：两个图形重叠后，无法选中内部（上层）的图形，总是选到底层大矩形。
- 根因：`find_element_at` 按 `image → video → shape` 的固定顺序遍历三个 `HashMap`，返回第一个命中的元素；大矩形包围小圆时，两者都命中，但底层矩形可能先被返回。

## 新建页面显示上一页内容（drafftink-edit / drafftink-app）
- 用户反馈：新建页面后仍显示上一页（第 0 页）的内容。
- 根因：两个 crate 的 `render_canvas` 完全忽略 `current_page`，元素选取写死为 `doc.pages.first()`（或 `doc.elements`），永远画第 0 页。每帧 `app.rs` 已把当前页 board 元素同步进 `doc.pages[idx]`，但渲染层不读它。
- 修复：`render_canvas` 新增 `current_page: usize` 参数，元素改为 `doc.pages[current_page]`（多页），`doc.pages` 为空时回退 `doc.elements`（遗留单页）；两处调用点传入 `idx` / `self.multi_page.current_page`。`drafftink-display` 原本就用 `current_page`，无需改。
- 约束：未改 drafftink-core；`cargo check -p drafftink-edit -p drafftink-app` 无 error / 无本文件 warning。本沙箱无 ffmpeg，video_player 测试仍环境性失败。
- 修复：引入全局 `z_index` 插入序号。
  - `IntegratedApp` 新增 `next_z_index: u64`。
  - `ShapeInstance` / `ImageInstance` / `VideoInstance` 各新增 `z_index: u64`。
  - 所有插入路径（`insert_shape_at`、`insert_image_at`、`insert_video_at`、`sync_path_videos`、`collect_embedded_videos`）在创建实例时分配并递增 `z_index`。
  - `find_element_at` 改为收集所有命中项，取 `z_index` 最大的（最上层）元素返回；新增 `update_best` 辅助。
  - 三个 `draw_*_overlay` 绘制循环按 `z_index` 升序排序后再绘制，确保后插入的元素渲染在更上层，与命中检测结果一致。
- 测试：新增 `overlapping_shapes_selects_topmost`：底层大矩形 z=0，上层小圆 z=1，点击圆心选中 `small`；点击大矩形内小圆外区域选中 `big`。
- 验证：`cargo clippy -p drafftink-desktop --all-targets` 改动文件 0 警告；`app::tests` 4 个测试全过。本沙箱无 ffmpeg，7 个 `video_player` 测试环境性失败，与本次改动无关。

## 重叠图形进一步：Ctrl/Cmd+单击向下穿透选中（drafftink-desktop）
- 用户再次反馈：大矩形（蓝色选中框）盖住内部小圆后，普通单击仍无法选中小圆。
- 根因：若大矩形后于小圆插入（z_index 更高），「最上层命中」策略会始终选中大矩形；没有机制选中下方的圆。
- 修复：
  - 新增 `find_all_elements_at`，返回指针下所有命中元素并按 `z_index` 降序排列。
  - `handle_canvas_click` 接收 `modifiers: &egui::Modifiers`。
  - 普通单击仍选最上层；按住 Ctrl（Windows/Linux）或 Cmd（macOS）单击时，若当前选中项在命中栈中，则循环选中下一层（`next = (pos + 1) % len`），实现穿透/循环选择。
  - 调用点同步传入 `ctx.input(|i| i.modifiers)`。
  - 移除已废弃的 `update_best` 与未使用的 `find_element_at`，避免 dead_code 警告。
- 测试：新增 `ctrl_click_cycles_through_overlapping_shapes`：小圆 z=1 在上，大矩形 z=0 在下；普通点击选 small；Ctrl+点击切到 big；再 Ctrl+点击回到 small。
- 验证：`cargo test -p drafftink-desktop --bin drafftink-desktop app::tests` 5 个测试全过；`cargo clippy -p drafftink-desktop --bin drafftink-desktop --tests` 改动文件 0 警告。

## 视频解码默认上限提到 4K（drafftink-desktop）
- 用户要求：把视频播放默认分辨率上限从 1080p（1920）提到 4K（3840）。
- 改动（仅在 `crates/drafftink-desktop/src/video_player.rs`，未动 drafftink-core）：
  - `new()` 默认 `max_dim` 由 `1920.0` → `3840.0`（`new_with_max_dim` 第二参数）。
  - 同步修正全部相关注释：doc 注释「默认 1920」→「默认 3840」；模块头部智能降维说明（4K≈33MB → 8K≈130MB）；`PRELOAD_FRAMES` 内存预算由 `8MB×6≈48MB` 改为 `33MB×6≈198MB`（仍远在 500MB 防线内）；`new` 便捷入口注释；测试 helper 注释（默认上限 1920 → 3840）。
- 影响：源 ≤4K 按原分辨率解码不缩放；仅源 >4K（如 8K）才压到 3840 长边。单帧 4K≈33MB，预加载缓冲 6 帧≈198MB，仍满足 500MB 内存防线。
- 验证：`cargo clippy -p drafftink-desktop --bin drafftink-desktop --tests` 改动 crate 0 警告（其余 crate 警告为既有技术债）。
