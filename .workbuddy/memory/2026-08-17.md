# 2026-08-17

## 形状工具交互模型修正（drafftink-desktop）
- 采纳用户反馈，将形状插入后的默认状态从「自动选中（显示边框+抓手）」改为「**插入即固定**」：
  - 插入后 `selected_shape_id = None`，不显示边框/抓手，像普通背景元素。
  - 单击该形状 → 选中（出现 RectInteraction 边框+抓手供微调）。
  - 单击空白处（不在任何形状矩形内）→ 取消选中。
  - 放置后本帧用 `skip_select` 标记，避免放置点击被误判为选中/取消选中。
- **去掉 Escape 取消选中**：保留 Escape 仅用于取消「点击放置」模式本身；原因是授课模式（F5）需要全局快捷键（Ctrl+S / Esc 退出），不能让 Escape 被单个元素取消选中占用。
- 实现要点：`draw_shape_overlay` 中仅 `selected_shape_id == key` 的形状才创建 RectInteraction 并显示边框/抓手；其余纯 `draw_shape` 渲染。命中检测用 `r.expand(4.0).contains(pos)`。
- 视频/图片叠加层暂维持原行为（插入即显示边框+抓手），本次未改。
- 验证：`cargo check`/`cargo clippy -p drafftink-desktop --all-targets` 均 0 警告（仅 nom 传递依赖告警）；`shape_renderer` 6/6、`interactive_rect` 17/17 单测通过。

- 用户要求把视频、图片也统一为与形状一致的交互：插入即固定（无边框/抓手/控件），单击才选中进入微调；单击空白取消选中；不绑定 Escape。
- 新增字段 `selected_video_id: Option<String>`、`selected_image_id: Option<String>`（仅备课模式有效）。

  - 选中判定：单击矩形或进度条区域 → 选中；单击空白 → 取消选中（备课、非放置、非拖拽、本帧未用于放置时）。
  - 仅选中态才绘制边框/抓手 + 暂停/静音按钮 + 进度条；未选中仅渲染视频帧。授课模式本就 `prepare=false` → 只读，无控件。
  - 放置完成帧用 `skip_select=true` + `selected_video_id=None`，避免放置点击误判。
- `draw_image_overlay` 重构：对称处理，仅选中态创建 RectInteraction 并显示边框/抓手；纹理绘制在更新后的 rect 上、overlay 绘制其上方。
- 两个叠加层的选择 `if` 已折叠 `collapsible_if`，清理后 `cargo clippy -p drafftink-desktop --all-targets` 0 警告（仅 nom 传递依赖）。
- 验证：clippy 0 警告；`shape_renderer` 6/6、`interactive_rect` 17/17 通过。视频/图片交互为运行时 UI 行为，需手动验收。

## 统一选中态：三套 *_id 合并为 selected_element_id
- 用户要求修复「选中边框阻挡点击 / 单击空白无法取消选中」并统一交互范式。重构 drafftink-desktop `app.rs` 与 `interactive_rect.rs`：
  - 删除 `selected_shape_id/selected_video_id/selected_image_id` 三字段，合并为单一 `selected_element_id: Option<SelectedElement>`（`SelectedElement` 枚举含 Shape/Video/Image(String)）。
  - 新增 `find_element_at(pos, screen)`：**只**用 `user_rect`/`world_rect` 逻辑矩形命中检测，绝不含边框 2px / grip 8px（修复「边框阻挡点击」）。新增 `handle_canvas_click(pos, screen)`：命中→选中（已选中则保持），空白→取消选中（统一「单击空白取消选中」范式，不绑定 Escape）。
  - `update()` 在叠加层绘制前、备课模式下、`primary_pressed` 时调用 `handle_canvas_click`。
    - 选用 **press** 而非任务字面的 `pointer_button_released`：release 会因「拖拽后释放落在图形外」误判为取消选中，且 release 帧 `active_drag` 仍占用导致普通单击无法选中；press 与既有已验证行为一致，规避该回归。
  - 修复 `RectInteraction::update` 潜藏 bug：指针释放时未归还全局拖拽守卫 `active_drag`，导致首次拖拽后该守卫永久占用、其它元素再也无法拖拽/选中。改为 `primary_down` 时应用拖拽、`!down` 时 `*active = None` 归还守卫。
  - 三个叠加层移除各自内联的选中判定块，`selected` 判定统一改为 `selected_element_id == Some(SelectedElement::X(key))`；移除了不再使用的 `skip_select` 与 image 叠加层的 `pointer_*` 临时变量。
- 新增单测（app.rs `tests`）：`click_blank_space_deselects`、`click_shape_selects`、`hit_test_uses_user_rect_only`，均通过。
- 验证：`cargo clippy -p drafftink-desktop --all-targets` 在改动文件 0 警告；`cargo test -p drafftink-desktop` 我的 3 个新测试 + `interactive_rect` 17 + `shape_renderer` 6 全过。
- 注意：本沙箱无本地 `ffmpeg.exe`，`video_player` 下 7 个测试（需本地 ffmpeg）环境性失败，与本次改动无关（未触碰 video_player.rs）。用户本机装有 ffmpeg 时应全绿。

## 视频加载/播放卡顿修复（drafftink-desktop）
- 用户反馈「加载视频时非常卡」。根因两类：
  1. **加载卡**：`VideoPlayer::new` 在 `update()` 调用链里同步执行（ffprobe×2 + `-hwaccels` + 对 4 个硬件后端逐个 ffmpeg 首帧探测），而 `ffmpeg_decode_args` 把 `-re`（实时限速）写死，探测也走 `-re` 且用 `.output()` 同步等进程结束 → 某个后端初始化慢时阻塞 UI 线程 1–3 秒；进授课 `collect_embedded_videos` 还会对每个内嵌视频串行调一次 `new`，N 视频卡 N×秒。
  2. **播放卡**：`draw_video_overlay` 每帧 `ctx.load_texture(...)` 反复分配 8MB GPU 纹理并触发旧纹理 GC；解码线程每帧 `vec![0u8; 8MB]` 重复分配。
- 修复（video_player.rs + app.rs）：
  - `ffmpeg_decode_args` 新增 `realtime: bool` 参数，仅真正播放/seek 重启进程时加 `-re`，首帧探测 `realtime=false`（不再限速、不再卡 UI）。回归测试 `probe_args_no_re` / `playback_args_have_re` 锁定。
  - `Frame.rgba` 改为 `Arc<[u8]>`，解码线程用 `std::mem::take(&mut buf)` 零拷贝移交，渲染侧借用（不再每帧 8MB clone）。
  - 渲染侧废弃每帧 `load_texture`，改为**复用 `TextureHandle` + `.set()`**，每帧仅一次 GPU 上传。
- 编译：`egui 0.29.1` 的 `ColorImage` 仅含 `size`/`pixels` 字段（无 `rgba/width/height`），`TextureHandle::set(&mut self, impl Into<ImageData>, TextureOptions)`；构造用 `ColorImage::from_rgba_unmultiplied([w,h], &frame.rgba)`。`cargo clippy -p drafftink-desktop --all-targets` 改动文件 0 警告。

- 用户反馈「新建页面后画布仍显示第一页内容」。根因：宿主层三套叠加层（shape/video/image 的全局 `HashMap`）**没有页面归属**，翻页/新建页后旧页叠加层仍被绘制在当前画布上（文档层 `drafftink-edit/render.rs` 此前已按 `current_page` 选页，故问题只在宿主叠加层）。
- 修复（`crates/drafftink-desktop/src/app.rs`，未动 `drafftink-core`）：
  - `ShapeInstance`/`ImageInstance`/`VideoInstance`/`InsertedVideo` 各新增 `page: usize` 字段（位于 `z_index` 之后）。
  - `IntegratedApp` 新增 `last_page: usize`（`new()` 初始化 0），用于检测翻页清空跨页选中态。
  - 新增 `current_canvas_page()`：`Prepare → self.edit.multi_page.current_page`；`Teach → self.display.multi_page.current_page`。
  - 所有插入点写入所属页：`insert_video_at`(InsertedVideo+VideoInstance)、`insert_image_at`、`insert_shape_at`、`sync_path_videos`(VideoInstance 用 `iv.page`)、`collect_embedded_videos`(VideoInstance 用 `slide_idx`)。
  - 渲染/命中均按 `cur_page` 过滤：`find_all_elements_at`（图/视/形三循环）、`draw_shape_overlay`、`draw_image_overlay`、`draw_video_overlay` 收集循环均加 `if inst.page != cur_page { continue; }`。
  - `update()` 顶部加翻页检测：`let cp = self.current_canvas_page(); if cp != self.last_page { self.selected_element_id = None; self.last_page = cp; }`，避免旧页选中边框残留。
- 测试 helper `sample_shape` 补 `page: 0` 字段。
- 验证：`CARGO_TARGET_DIR` 唯一化规避 Win 文件锁；`cargo clippy -p drafftink-desktop --bin drafftink-desktop --tests` 改动文件 0 警告（其它 crate 既有 `uninlined_format_args` 告警无关）；`cargo test -p drafftink-desktop --bin drafftink-desktop app::tests` 5/5 通过；全量 `cargo test -p drafftink-desktop` 37 passed / 7 failed，7 失败均为 `video_player::tests::*`（沙箱无 `ffmpeg.exe`，环境性，未触碰 `video_player.rs`）。

## 视频进度条 Seek 卡顿修复（非阻塞 + 双缓冲 + UI 节流）
- 用户反馈拖动进度条 UI 卡顿。架构事实纠正：drafftink-desktop **并非** libavcodec/ez-ffmpeg 内联解码，而是 shell-out 本地 `ffmpeg.exe`（内置 FFmpeg 为 2026-07 git master，与 `ffmpeg-next 8.1.0` ABI 不匹配无法编译）；解码经 `decode_loop` 后台线程 → 有界 `sync_channel::<Frame>(N)` → UI `try_recv()`。`Frame.rgba` 已是 `Arc<[u8]>`，**零拷贝本就存在**，卡顿真因在别处。
- **卡顿真因**：旧 `seek()` 在 UI 线程 `self.thread.take()` + `h.join()` + `self.child.wait()`，Windows 上杀进程常需 100–500ms → 拖动时主线程卡死。
- 修复（`crates/drafftink-desktop/src/video_player.rs`，未动 `drafftink-core`）：
  - **预加载双缓冲**：`sync_channel` 容量从 1 提至 `PRELOAD_FRAMES = 6`（有界背压，单帧 ≤8MB 故上限 ≈48MB，远在 500MB 内存防线内）。
  - **非阻塞 seek**：`seek()` 开头合并连续跳转（`if self.seeking { self.pending_seek = Some(t); return; }`）；旧进程/线程/通道摘下交新起「video-reaper」后台线程 `kill`+`wait`+`join`，UI **立即返回**；新进程用独立 `new_stop` 标志与旧线程解耦；失败分支置 `seeking=false` 兜底。
  - **先冻结后瞬切**：`draw_video_overlay` 在 `try_recv` 失败时保留 `last_tex`（旧帧冻结），`seek` 时通道被换掉自动冻结，首帧到达 `try_recv` 瞬间刷新（`self.seeking=false` 并顺带发起 `pending_seek`）。
  - `begin_scrub()` 只清预加载缓冲（**不置 `seeking`**，否则紧随的 `seek()` 会误 coalesce 成 no-op）；新增 `clear_preload()`。移除未使用的 `is_seeking()`（dead_code）。
- UI 节流（`app.rs` `draw_video_overlay`）：
  - `VideoInstance` 新增 `last_seek_request_ms: Option<Instant>`；3 个构造点补 `None`。新增常量 `SEEK_THROTTLE_MS = 16`。
  - 拖动 `pointer_down` 仅每 ≥16ms 才发一次真实 `seek()` 重启；进度条数值 `seek_target_ms`/`current_ms` 仍每帧更新（廉价、保持手柄平滑）。
  - 按下进度条瞬间调 `begin_scrub()`（清缓冲、冻结旧帧）；释放时发最终精确定位 `seek()`。
- 验证：`CARGO_TARGET_DIR=/c/tmp/dt_verify cargo clippy -p drafftink-desktop --bin drafftink-desktop --tests` **drafftink-desktop 0 警告**（其它 crate 既有 `uninlined_format_args` 等告警无关）；`cargo test -p drafftink-desktop` 37 passed / 7 failed，7 失败均为 `video_player::tests::*`（沙箱无 `ffmpeg.exe`，环境性）。`seek_restarts_and_decodes` 契约（seek 后 3s 内 `try_recv().is_ok()`）在非阻塞改写下仍满足。
