## SM4 国密实现修复（drafftink-core/src/sm4.rs）

将生成式 S-box 替换为 GB/T 32907-2016 表 1 的权威硬编码常量 `SM4_SBOX`（256 字节，pub const），
并新增 `sm4_sbox(byte)` 取值函数。删除了旧的 GF(2⁸) 逆元 + 仿射生成逻辑（`gf_mul`/`gf_inv`/`build_sbox`/`sbox()`）。

### 关键正确性结论（可复用）
1. **SM4 最终输出字序必须反序**：32 轮后状态为 (X32,X33,X34,X35)，标准密文应为 (X35,X34,X33,X32)。
   原实现按正序输出，导致密文恰好是正确值的字反转（KAT 失败但内容正确）。已在 `crypt_block` 末尾 `x.iter().rev()` 修正。
2. **S-box 索引 0x82 的权威值 = 0x8A**（非用户以为的 0x66）。值 0x82 落在索引 0xA4，相邻的 0x66 在 0xA5。
   用户提供的硬编码数组本身正确（首元素 0xD6、末元素 0x48、0xEF→0x84 均对）。
3. **全零测试向量 ≠ 附录A 示例1**：key/pt 全零时 SM4 密文为
   `9F 1F 7B FF 6F 55 11 38 4D 94 30 53 1E 53 8F D3`（非 `68 1E DF 34...`）。已纠正 KAT 测试。
4. CK 生成逻辑 `ck(j)=(4i+j)·7 mod 256` 拼接，FK=[0xA3B1BAC6,0x56AA3350,0x677D9197,0xB27022DC] 均正确，保留。

### 验证结果
- `cargo test -p drafftink-core --lib sm4`：4/4 通过（KAT 附录A + 全零向量 + S-box 自检 + roundtrip + material 确定性）。
- `cargo clippy -p drafftink-core`：零警告（已用 `repeat_n` 消除 `manual_repeat_n`）。
- `cargo build --release -p drafftink-core`：零警告。

## GB/T 7408.1-2023 日期标准化模块（drafftink-core/src/utils/date_time.rs）

新建 `GbDateTime`（核心 `NaiveDate`）+ `GbDateTimeError{InvalidFormat,OutOfRange,InvalidSeparator}`，作为 `utils::date_time` 子模块挂入 `drafftink-core`（已在 `utils.rs` 加 `pub mod date_time;`，`lib.rs` 加 `pub use utils::date_time::{GbDateTime, GbDateTimeError};`）。

### 关键实现点（已验证）
- 解析优先级：a.YYYYMMDD → b.YYYY-MM-DD → c.YYYYMMDDTHHMMSS（仅取日期）。
- 容错：`/` → `-` 归一；含 `/` 且仍失败→`InvalidSeparator`，否则→`InvalidFormat`。
- 校验：年份 [1900,2100]，负数年份前导 `-` 直接判 `OutOfRange`（chrono %Y%m%d 对前导负号整体解析失败，须提前拦截）。
- Display 默认 `YYYY-MM-DD`；`to_basic_string()` → `YYYYMMDD`；实现 `FromStr`。
- **chrono 0.4.45 坑**：`NaiveDate::year/month/day` 已改为 `Datelike` trait 方法（inherent 变 private），须 `use chrono::Datelike;` 否则 E0624 编译失败。

### 验证
- `cargo test -p drafftink-core --lib date_time`：13/13 通过（含 5 个必测用例 + 闰年/范围/分隔符/roundtrip/FromStr）。

### 关键事实：源 PDF 可提取性（重要）
- **仅 GB/T 4754-2017 可从 PDF 机器提取**（pymupdf 提取 90k 中文字符，真实可用）。该 PDF 用全角数字（０１等）+ 全角空格，需 `norm()` 归一后再解析；中类(3位)名称为 CID 字体不可提取，故仅含门类/大类/小类三级。
- **4658/6864/8561/4881/3304/2261.2 六个 PDF 均 CID 字体/图像，文本层零中文**（pypdf/pymupdf 提取 CJK 计数=0，4881 甚至 0 字符）。本沙箱无 OCR 引擎。故这 6 张表的代码/名称取自**对应标准已发布的代码表**（非从本批 PDF 逐字节提取），已在模块注释与文档中明确标注来源与"需与官方文本核对"。
- 提取脚本经验：`pymupdf` 对全角数字需手动 `chr(ord-0xfee0)` 归一；heredoc 内含 `'''` 会触发 bash 引号解析失败，应改用 `<<'PY'` 或将脚本写为 .py 文件再执行。
