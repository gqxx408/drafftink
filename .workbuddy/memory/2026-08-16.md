## drafftink-desktop：备课模式「🎬 多媒体」插入视频

任务：顶边栏加「🎬 多媒体」按钮 → 系统文件选择框 → 选视频 → 当前幻灯片画布中心插入视频并自动播放叠加层；V 键保留，改走同一入口。

### 关键架构事实（与用户设想不同，易踩坑）
- **运行时的备课顶栏在 `drafftink-edit/src/app.rs` 的 `EditApp`（`TopBottomPanel::top("editor_toolbar")`），不是 `ui/prepare.rs`**。后者（`DesktopApp` 版）是**死代码**，未被 `IntegratedApp::update` 调用（update 备课分支调的是 `self.edit.update()` = `EditApp`）。所以按钮必须改 `drafftink-edit`。`EditApp` 已有 `pub teach_requested`/`save_requested` 模式 → 照抄 `media_pick_requested` 字段 + Default。
- `EditApp` 里**已经有一个空的 `if label_btn(ui, " 多媒体", ...).clicked() {}` 占位按钮**（app.rs ~378），只是没接线。改成 `🎬 多媒体` 并置位 `media_pick_requested`。
- **`VideoElement` 没有 `video_path` 字段**，只有 `resource_id: String`（约束禁止改 `drafftink-core`）。本地文件路径用 `file://` 前缀写入 `resource_id`，叠加层据此直开本地文件。
- 文档层 `CoursewareDoc.pages: Vec<PageContent>`，而 `PageContent.elements: Vec<Element>`（legacy），**装不下 `ElementData::Video`**（`to_legacy()` 对其返回 None）。故视频元素不能塞进 doc，改为在宿主 `IntegratedApp` 用 `inserted_videos: Vec<InsertedVideo>` 记录（含完整 `ElementData::Video` 以备将来落盘），并在 `video_instances` 建可播放叠加层。这是受约束下唯一可行路径。
- `Camera::world_to_screen` 映射的是**画布viewport坐标**（原点=画布左上），但 `draw_video_overlay` 用 `ctx.layer_painter` 在全窗口屏幕空间绘制 → 备课时锚定视频会偏上偏左一个面板偏移。故在 `EditApp` 暴露 `pub canvas_offset: [f32;2]`（=`canvas_rect.min`），`draw_video_overlay` 对 `world_rect` 视频补上该偏移（授课模式 `display.camera` 全屏，偏移 0）。

### 实现要点
- 按钮/ V 键 → `IntegratedApp::request_video_pick(ctx)`：后台 `std::thread::spawn` 弹 `rfd::FileDialog`（过滤 mp4/mkv/mov/avi/webm/flv/wmv），选中后 `sink(Arc<Mutex<Vec<PathBuf>>>).push` + `ctx.request_repaint()`。`egui::Context` 可跨线程 clone，`request_repaint` 安全。
- 每帧 `consume_pending_videos` 取出路径 → `insert_video_from_path`：按 `edit.camera` 算画布中心世界坐标 + 默认 640×360（不超过画布宽 60%）→ 建 `ElementData::video` → 记入 `inserted_videos` → `video_instances` 建实例（`world_rect` 锚定中心，自动播放）。
- `sync_path_videos`：幂等，为 `inserted_videos` 中缺实例的补建；在 `enter_teach`/`exit_teach` 后调用（因为 `enter_teach` 会 `video_instances = instances` 整表替换），保证授课/回到备课视频不丢。
- V 键原先的 `load_test_video`（硬编码 test 视频）已删除，统一走文件选择框。
- 拖拽/缩放/暂停/静音：复用 `draw_video_overlay` 现有交互（`inst.offset`/`user_scale`/`player` 全在屏幕空间），路径视频天然支持。

### 偏离需求原文的 3 处（均已落地可用）
1. rfd：本就是 workspace 依赖（`rfd.workspace = true`），未新增 `rfd="0.15"`（会与现有 key 冲突；且离线环境 `cargo update` 连不上代理 127.0.0.1:7890，无法拉 0.15，锁文件锁 0.14）。功能 API 一致。
2. `video_path` 字段 → `resource_id` 的 `file://` 前缀（约束禁改 core）。
3. V 键不再自动播硬编码测试视频，而是同样弹文件框（用户明确要求「改成调用同一函数」）。

### 视频叠加层 8 方向拖拽缩放重写（drafftink-desktop）
- 需求：替换仅右下角 grip 的统一缩放，改为 8 方向 + 内部移动，宽高完全独立（不锁比例）。
- 数据模型：`VideoInstance` 删除 `offset:[f32;2]`，新增 `user_rect: Option<egui::Rect>` 作为屏幕空间唯一真相来源；`world_rect` 仅当 `user_rect==None` 时作默认矩形（相机锚定/居中 60% 16:9），一旦用户拖拽即锁定屏幕矩形、不再跟随相机。
- 删除 `VideoPlayer.user_scale` 字段 + `set_user_scale`（统一缩放被 user_rect 取代）；profiler 与键盘 +/- 缩放同步改为围绕中心缩放 `user_rect`（带 40×30 最小尺寸保护）。
- 命中检测：9 宫格（角12×12 > 边6px > 内部），新增模块级 `HitZone` 枚举（8方向+Move+Pause+Mute+Outside）取代原局部 `Hit` 枚举与 `VideoDragMode`。`video_drag` 字段类型改为 `Option<(String, HitZone)>`。
- 最小尺寸保护：任一维 < 40/30 则整体回退到拖拽前矩形（不应用），防消失。
- 视觉：2px 灰(150,180)/亮蓝(0,150,255) 边框；悬停角画 8×8 亮蓝方块 grip；悬停边 3px 亮蓝高亮；暂停/静音按钮顶边右上角随 rect。光标按区域设置，拖拽中跟随拖拽区。
- 验证：`cargo clippy -p drafftink-desktop --all-targets` → desktop 自身 0 警告（warning 仅来自 drafftink-edit/display 既有代码）；`cargo test -p drafftink-desktop` → 10 passed；全 workspace `cargo test` 后台运行中确认 269 不破坏。

## drafftink-desktop：图片元素 + 8 方向交互抽取为公共组件（本会话）

在「视频 8 方向拖拽」之上，新增**图片元素**完整链路，并把视频/图片共用的命中检测 + 缩放 + 移动逻辑抽成独立模块。

### 架构变更（纠正上方"8 方向拖拽重写"条目）
- 上条目描述的「模块级 `HitZone`（含 Pause/Mute）+ `video_drag: Option<(String, HitZone)>`」**已被抽取取代**：
  - 新增 `crates/drafftink-desktop/src/interactive_rect.rs`（需在 `main.rs` 显式 `mod interactive_rect;` 声明，否则 binary crate 找不到；编译错 `E0432`）。
  - `HitZone` 移入该模块，**去掉 Pause/Mute**（按钮是视频专属，仍由 `draw_video_overlay` 单独处理）。
  - `RectInteraction { id, rect, hovered, active_drag }` 提供 `hit_test` / `apply_drag`(纯) / `revert_if_too_small`(纯) / `update` / `draw_overlay` / `cursor_for`(私有)。常量 `EDGE=6, CORNER=12, MIN_W=40, MIN_H=30`。
  - 全局唯一拖拽守卫改为 `IntegratedApp.active_drag: Option<(egui::Id, HitZone)>`（原 `video_drag` 字段删除）；`update` 在按下且守卫空闲时认领，保证视频/图片跨实例互斥。
  - `Pos2 - Pos2` 在 egui 得 `Vec2`：角命中区必须用 `r.right_top() - Vec2::new(...)`（不是 `- Pos2::new(...)`），否则 `E0308`。

### 图片功能链路
- 顶边栏（drafftink-edit `EditApp`）新增「🖼 图片」按钮（紧邻「🎬 多媒体」），置位 `image_pick_requested: bool`（仿 `media_pick_requested`，含 Default init）。
- `IntegratedApp` 新增：`image_instances: HashMap<String, ImageInstance>`、`pending_images: Arc<Mutex<Vec<PathBuf>>>`、`image_textures: HashMap<PathBuf, TextureHandle>`。
- 入口：`request_image_pick(ctx)`（后台 `rfd` 线程，过滤 png/jpg/jpeg/gif/bmp/webp）→ 主循环 `consume_pending_images` → `insert_image_from_path`（画布中心默认 480×270，不超画布宽 60%，`world_rect` 锚定）；`draw_image_overlay` 懒加载纹理（`image` crate `load_from_memory`，命中前先 `contains_key` 再 `insert`，避免 `get` 的不可变借用跨过 `insert` 的借用冲突）、`painter.image` 绘制、复用 `RectInteraction`（**无暂停/静音按钮**）、40×30 最小尺寸保护。
- 快捷键：I 键弹图片框（仿 V 键视频）。`image_instances` 不受 `enter_teach`/`exit_teach` 整表替换影响，故无需 `sync_path_images`；图片目前仅宿主层叠加层、不落盘（与视频同因：`to_legacy()` 对 `ElementData::Image` 返回 None）。

## drafftink-desktop：9 种形状工具系统（Shape Tool）
